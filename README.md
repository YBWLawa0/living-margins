# 众生行记 · Living Margins

> 让每一页，遇见读过它的人。

实体书页感知与数字批注伴读系统（当前版本：V5）。

摄像头循环观察书本：看到已注册封面时自动选择书籍，打开书后持续识别当前页码。封面和页码都有独立的多次确认，单帧误识别不会立即切换书籍或页面。

完整的路线演变、现场测试、技术决策和后续计划见 [`DEVELOPMENT_LOG.md`](DEVELOPMENT_LOG.md)。

## 最快开始

1. 如果主识别程序正在运行，先按 `Q` 退出，释放摄像头。
2. 双击 `add_book.bat`，把封面对准摄像头。绿色轮廓表示已自动找到封面；没有绿色轮廓时，把封面放进黄色取景框。
3. 按空格拍照。程序会自动裁正封面、执行 OCR、提取标题并生成系统编号。
4. 在审查窗口核对书名：识别正确可直接确认，少量错误只需修改对应文字，也可以选择重新拍照。
5. 重新运行 `run.bat`，把封面稳定展示约 2～3 秒。
6. 界面出现 `BOOK 书籍ID | COVER MATCHED` 后打开书，程序会自动开始识别页码。
7. 正常翻页；按 `S` 清除旧页码锚点，按 `A` / `D` 手动修正跨页，按 `Q` 或 `Esc` 退出。

## ESP32 到货前的虚拟屏幕测试

1. 先双击 `run.bat` 启动识别程序。
2. 再双击 `virtual_screen.bat`，打开一个 480×320 的虚拟设备屏幕。
3. 展示封面并打开书。虚拟屏幕会自动显示书名、已确认页码以及翻页/识别状态。
4. 页码稳定后可以点击“赞同”或“不赞同”，验证未来触摸屏的反馈链路。

虚拟屏幕不读取识别程序内部变量，而是每 0.5 秒访问 `http://127.0.0.1:8765/state`。ESP32 到货后可以直接消费同一个接口。状态示例：

```json
{
  "schema_version": 1,
  "revision": 12,
  "book_id": "try-n1-060455",
  "title": "TRY-新日语能力考试N1-语法必备",
  "pages": [74, 75],
  "status": "stable",
  "comment": {
    "id": "comment-20260826120000-a1b2c3",
    "page": 74,
    "text": "这里的语法接续与上一节形成对照。",
    "author": "匿名读者"
  },
  "source": "page_ocr",
  "event": "page_confirmed",
  "updated_at": "2026-08-26T12:00:00.000+08:00"
}
```

只有书籍、页码或有效状态变化才会增加 `revision`，普通 OCR 帧不会制造更新噪声。翻页和重新识别期间会保留最后一次可信页码，直到新页通过共识确认。当前快照保存在 `runtime/state.json`，状态历史在 `runtime/events.jsonl`，按钮反馈在 `runtime/feedback.jsonl`。

## 录入页码批注

双击 `add_comment.bat` 打开批注管理窗口：

1. 选择已经注册的书籍。
2. 输入批注对应的实际页码、署名和内容。
3. 点击“保存批注”。主识别程序无需重启，约 1 秒内会重新检查当前页。
4. 摄像头确认到包含该页的跨页后，虚拟屏幕显示批注；此时赞同/不赞同按钮才会启用。
5. 点击已有批注可以修改、停用或删除。

每本书的批注保存在其目录下的 `comments.json`，例如 `books/try-n1-060455/comments.json`。同一个跨页同时存在多条批注时，系统先选择优先级更高的一条；优先级相同则选择状态中靠前的页。虚拟屏幕会明确显示批注实际对应的页码。

当前视觉层仍输出跨页而不是唯一可见页，因此“左右页/单页自动判定”仍是后续任务。现阶段应避免在同一个跨页的两页上都录入相同优先级的批注，或通过优先级明确希望展示哪一条。

## 拍照录入书籍

`add_book.bat` 的默认流程不再要求用户逐项输入 ID、书名和图片路径：

```text
摄像头拍照
→ 自动检测并透视裁正封面
→ OCR 所有封面文字
→ 根据字号、位置和置信度建议书名
→ 自动生成内部书籍 ID
→ 人工审查并确认
```

审查窗口会同时显示裁正后的封面、可编辑书名、无需编辑的系统编号和所有 OCR 文本。入库元数据会记录 OCR 原文、置信度以及已人工审查状态。

当前本地 RapidOCR 对中文、英文印刷体效果较好；日文、竖排文字和艺术字体可能需要较多修改。识别结果不会未经审查直接入库。

## 封面匹配方式

当前版本匹配本机 `books/` 中已经注册的书，不会根据互联网自动搜索任意书籍。每本书包含一份 `book.json` 和一张参考封面。

封面识别使用局部视觉特征和透视一致性，不依赖书名 OCR，因此可以适应一定程度的旋转、倾斜、远近变化和局部光照差异。匹配必须满足足够多的特征点和透视内点，并连续出现两次，才会切换当前书籍。普通内页在自动化测试中不会匹配成封面。

查看已经添加的书籍：

```powershell
.\.venv\Scripts\python.exe manage_books.py list
```

已有图片或需要更新同一本书时，仍可使用备用命令行工具 `manage_books.py add ... --replace`。

## 20 次翻页验证

V3.4 会自动创建一次测试会话。测试时正常阅读并连续翻页，不要按 `S`：

- 自动确认正确时按 `Y`，同一次确认只需标记一次。
- 自动确认错误时按 `N`。
- 页面停留后始终没有得到正确确认时按 `M`，表示漏检。
- 测试至少翻页 20 次后按 `Q` 正常退出。

测试标记不会参与识别或改变页码，只用于计算真实准确率。完全不按这些按键也可以运行，但统计中只会有识别速度和状态变化，不会伪造正确率。

## 状态说明

- `STABLE`：页码已经确认。
- `TURNING`：检测到运动，暂停 OCR，等待翻页结束。
- `VERIFYING`：正在收集连续一致的页码结果。
- `UNCONFIRMED`：没有可靠页码；程序不会用正文数字更新页面。

## 页码识别方式

1. 每帧检查运动、亮度、对比度和清晰度；黑屏、遮挡或严重模糊不会进入 OCR。运动必须在一个短窗口内多次出现才开始一次翻页事件，稳定前的阈值抖动不会重复创建事件。
2. 画面稳定且 OCR 空闲时，从最近缓冲中提交清晰度最高的帧；识别结束后再取当时最新的一组稳定帧，不建立任务队列。
3. OCR 始终读取完整画面；检测到的纸张范围只作为页脚位置的软坐标系，不裁剪图像。书本没有贴住画面底边时，页码仍可按相对书页位置进入候选。
4. 未确认或发现不同页码时尽快连续识别；确认后最短间隔约 1 秒继续后台复查。若一次 OCR 本身超过 1 秒，下一轮会在完成后立即使用最新帧。
5. 数字候选根据相对书页底部、页边距、OCR 置信度、页码奇偶、同一行中的位置和上一页状态评分；露在最外沿的底层纸页数字会被软降权。
6. 普通变化连续两次一致才更新；超过 `max_page_jump` 的变化允许进入候选，但必须连续三次一致。候选层不再用旧页码重复否决大跳页。
7. 单次无结果或单次错误不会清空、闪烁或覆盖已确认页码。
8. 翻页后超过约 3 秒仍未恢复时，自动忽略旧页的评分偏好重新捕获；当前可信页仍会保留，且不降低三次确认要求。

## 调试结果

当 `config.json` 中 `debug` 为 `true` 时，最新一次连续识别会覆盖写入 `debug/live/`。按 `S` 的初始帧还会单独保存在 `debug/时间戳/`：

- `raw.png`：实际送入 OCR 的完整高清帧。
- `metadata.json`：扫描模式和配置。
- `result.json`：全部数字候选、页码评分、最终结果和错误信息。

每次启动还会创建 `debug/sessions/时间戳/`：

- `events.jsonl`：逐行记录运动、OCR 耗时、原始候选、观察结果、共识变化、人工测试标记。
- `summary.json`：实时更新本次会话的扫描数、无结果次数、错误次数、确认延迟和标注准确率。
- `frames/`：只保存新待确认候选、页面确认、OCR 异常、每次重新捕获的首张失败画面和人工标记等关键帧，不保存普通视频帧。

封面扫描也会写入 `events.jsonl`：包括匹配书籍、特征匹配数、透视内点、封面面积、待确认进度和最终书籍切换。封面待确认与确认画面会保存到 `frames/`。

界面会持续显示最近 OCR 距今时间、单次耗时、本次观察、待确认进度和会话计数。即使程序测试中途异常退出，已经写入的事件和此前的摘要仍然保留。

## 主要配置

- `frame_width` / `frame_height`：摄像头请求分辨率。
- `camera_backend`：Windows 摄像头后端，默认 `MSMF`，失败时回退 `DSHOW`。
- `motion_threshold`：运动检测阈值；环境轻微晃动时可适当提高。
- `motion_start_frames` / `motion_window_frames`：短窗口内需要多少个运动帧才认定翻页，默认是 5 帧中至少 3 帧。
- `settle_seconds`：运动结束后等待稳定的时间。
- `sharp_buffer_frames`：稳定阶段保留多少帧用于选择最清晰图片。
- `min_ocr_confidence`：进入页码候选池的最低 OCR 置信度。
- `page_number_positions`：当前支持 `bottom_outer`，也可加入 `top_outer`。
- `confirmations_required`：普通页码变化需要连续一致的次数，默认 2。
- `large_jump_confirmations`：大跳页需要连续一致的次数，默认 3。
- `ocr_retry_interval_seconds`：尚未确认时 OCR 完成后的最短重试间隔。
- `ocr_verified_interval_seconds`：页码确认后的后台复查间隔，默认 1 秒。
- `auto_reacquire_seconds`：翻页后仍未恢复时，多久进入自动重新捕获评分，默认 3 秒。
- `min_frame_brightness` / `min_frame_contrast`：黑屏和遮挡过滤阈值。
- `max_page_jump`：正常跟踪时的大跳页惩罚范围，不是硬性拒绝条件；按 `S` 时完全忽略。
- `telemetry_enabled`：是否记录 V3.3 测试会话，默认开启。
- `telemetry_max_keyframes`：单次会话自动保存的 OCR 关键帧上限，默认 200；事件日志不受此限制。
- `books_directory`：本地书籍目录，默认 `books`。
- `cover_confirmations`：切换书籍所需的连续相同封面次数，默认 2。
- `cover_match_interval_seconds`：封面后台匹配的最短间隔。
- `cover_min_good_matches` / `cover_min_inliers` / `cover_min_inlier_ratio`：封面特征和透视验证阈值。
- `cover_ocr_min_confidence`：拍照录入时进入标题候选的最低文字置信度。
- `runtime_directory`：统一阅读状态、历史事件和设备反馈目录。
- `state_server_enabled`：是否提供状态 HTTP 接口。
- `state_server_host` / `state_server_port`：状态接口监听地址和端口，默认端口为 `8765`。
- `comment_refresh_interval_seconds`：当前页面稳定时重新检查批注文件的间隔，默认 1 秒。

旧配置中的 `left_page_roi`、`right_page_roi`、`roi_width_ratio`、`roi_height_ratio` 和 `scan_interval_seconds` 会被保留以兼容现有文件，但 V3 主流程不再使用它们。
